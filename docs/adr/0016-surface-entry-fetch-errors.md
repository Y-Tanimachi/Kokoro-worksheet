# ADR-0016: 記録の取得失敗を「記録なし」と区別して表示する

**Status:** Accepted
**Date:** 2026-09-24
**Deciders:** Y-Tanimachi（単独開発）

## Context

`src/utils/storage.ts` の `getEntries` は、Firestore からの取得に失敗すると例外を握りつぶして空配列を返していた。そのため通信エラーや権限エラーのとき、ホーム画面は「まだ記録がありません」と表示していた。詳細ページの `getEntry` も同じで、失敗すると `null` を返し、「データが見つかりません」と表示していた。

このアプリは自分の感情を記録するためのもので、積み上げた記録が消えたように見えるのは、一時的な表示の誤りでも利用者に強い不安を与える。

## Decision

- `getEntries` / `getEntry` は例外を握りつぶさず、ログを残したうえで投げ直す。
- `useWorksheetEntries` にエラー状態（`error`）と再取得の関数（`reload`）を持たせる。
- ホームの一覧は、取得に失敗したとき「記録を読み込めませんでした」「記録は消えていません」と表示し、再読み込みボタンを出す。感情レポートは、失敗しているあいだは表示しない。
- 詳細ページも取得失敗を「データが見つかりません」と区別し、再読み込みボタンを出す。

## Options Considered

### Option A: 空配列を返したまま、画面の文言だけ曖昧にする

「記録がないか、読み込めませんでした」のような文言にする案。
**Pros:** 変更が最小。
**Cons:** 本当に記録が無い新規ユーザーにも不安な文言が出る。再試行の手段も無い。

### Option B: ストレージ層で例外を投げ直し、フックでエラー状態を持つ（採用）

**Pros:** 「記録なし」と「取得失敗」を正確に出し分けられる。再読み込みの導線を付けられる。エラー処理の責務が、既存の構成（ADR-0005: Context とカスタムフック）に沿ってフックに集まる。
**Cons:** `getEntries` / `getEntry` を呼ぶ側すべてに例外処理が要る（現時点の呼び出し元は `useWorksheetEntries` と詳細ページの 2 箇所で、どちらも対応済み）。

### Option C: Firestore のオフラインキャッシュ（永続化）を有効にし、失敗時はキャッシュを表示する

**Pros:** 通信できなくても、前に見た記録が表示される。
**Cons:** 永続化の設定とキャッシュの整合性という新しい論点が増える。キャッシュが空の端末では結局失敗を表示する必要があり、Option B が前提として要る。

## Trade-off Analysis

利用者にとって最悪なのは「記録が消えた」と誤解することであり、それを確実に防げるのは失敗を失敗として表示する Option B だけだった。Option C は Option B に上乗せできる改善なので、オフライン閲覧の要件が出たら改めて検討する（ADR-0010 のオフライン方針とあわせて）。

## Consequences

- 通信や権限のエラーで「まだ記録がありません」「データが見つかりません」と表示されることはなくなった。
- 今後 `getEntries` / `getEntry` を新たに呼ぶときは、例外処理を書く必要がある。
- 保存（`saveEntry`）と削除（`deleteEntry`）は以前から例外を投げ直している。ただし詳細ページの削除は、失敗時の表示がまだ無い。
