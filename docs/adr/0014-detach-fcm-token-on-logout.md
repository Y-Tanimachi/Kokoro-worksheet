# ADR-0014: ログアウト時に端末の FCM トークンを破棄してアカウントから切り離す

**Status:** Accepted
**Date:** 2026-09-24
**Deciders:** Y-Tanimachi（単独開発）

## Context

リマインダー通知は `user_settings/{uid}.fcmToken`（ユーザー 1 人につき 1 トークン）宛てに送っている。ログアウト処理は Firebase Auth のサインアウトだけで、トークンには何もしていなかった。そのため次の 2 つの問題があった。

1. ログアウトした後も、その端末にリマインダーが届き続ける。
2. 共有端末で A がログアウトし、B がログインして通知を ON にすると、FCM トークンは端末（ブラウザ）単位なので A と B に同じトークンが保存される。その結果、A 宛てのリマインダーが B の使う端末に届く。通知文は固定なので記録内容は漏れないが、使っていない人に通知が届く。

なお「複数端末では最後に通知を ON にした（またはログインした）端末にだけ届く」ことは想定どおりの仕様とし、今回は変えない。

## Decision

ログアウト時、サインアウトより前に `detachDeviceToken`（`src/utils/notifications.ts`）を呼ぶ。

1. 通知許可が `granted` の端末に限り、この端末のトークンを取得する（`default` で `getToken` を呼ぶと許可プロンプトが出るため）。
2. `deleteToken` でトークン自体を無効化する。以後この端末でどのアカウントが通知を ON にしても新しいトークンが発行されるため、A と B が同じトークンを共有しない。
3. `user_settings` に保存されているトークンがこの端末のものなら `null` に戻す。別端末のトークンなら触らない。
4. `notificationsEnabled` は利用者の設定として残す。再ログイン時は既存の再同期処理（`useNotificationSettings`）が新しいトークンを保存するので、その端末でリマインダーが再開する。

切り離しに失敗してもログアウトは止めない。オフライン時は Firestore の書き込みが resolve しないため、5 秒で打ち切る。

## Options Considered

### Option A: Firestore の fcmToken を null にするだけ

**Pros:** 実装が小さい。
**Cons:** 端末側のトークンは生きたままなので、B がログインして通知を ON にすると同じトークンが B に保存される。A の書き込みが失敗した場合、A と B がトークンを共有する状態が残る。

### Option B: deleteToken でトークンを破棄し、Firestore も片付ける（採用）

**Pros:** トークンそのものが無効になるので、Firestore の更新が失敗しても送信時に `not-registered` となり、通知 API の自動クリーンアップで回収される。アカウントごとに別のトークンになる。
**Cons:** ログアウトに FCM への通信が入り、少し遅くなる。再ログインのたびにトークンが発行し直される。

### Option C: サーバー側で同じトークンを持つ複数ユーザーを検出して除外する

**Pros:** クライアントの変更が要らない。
**Cons:** どのユーザーが「今の持ち主」かをサーバーは判断できない。1 の「ログアウト後も届く」も解決しない。

## Consequences

- ログアウト後、その端末にはリマインダーが届かなくなる。
- 共有端末でも、アカウントごとに別のトークンが保存される。
- 通知 ON のまま再ログインすると、その端末でリマインダーが自動で再開する。
- ログアウトを経ずにセッションが消えた場合（ブラウザのデータ削除など）は対象外。この場合は FCM 側でトークンが失効し、送信時の自動クリーンアップで回収される。

## Action Items

1. [ ] デプロイ後、ログアウトした端末に定時通知が届かないことを実機で確認する
2. [ ] 同じ端末で別アカウントにログインして通知を ON にし、`user_settings` の 2 アカウントの `fcmToken` が別の値（ログアウトした側は `null`）になることを確認する
