# ADR-0015: ワークシートのテキスト項目を 1 項目 300 文字までに制限する

**Status:** Accepted
**Date:** 2026-09-24
**Deciders:** Y-Tanimachi（単独開発）

## Context

ワークシートのテキスト項目（トリガー・自動思考・代替思考・反応・反省・次に試すこと・自分への褒め言葉の 7 項目）には文字数の上限が無かった。一方、応援メッセージを生成する `/api/ai-message` は、コスト制御とプロンプトインジェクション対策のために入力本文を 2000 文字までに制限している（ADR-0008）。

クライアントは 7 項目にラベルを付けて連結して送るため、記入量が多いと本文が 2000 文字を超える。するとサーバーは 400 を返し、クライアントはレスポンスの中身を確かめないまま定型文（「よく頑張りましたね！」）を表示していた。ユーザーには、書きすぎたせいで AI の応答が定型文になったことが分からなかった。

## Decision

- 7 項目それぞれの入力欄に `maxLength` を付け、1 項目 300 文字までにする。日本語は 1 字 = 1 文字として数える（`String.length`、UTF-16 単位。絵文字などは 2 と数える）。
- 上限の 8 割（240 文字）に達したら入力欄の下に残り文字数を出し、300 文字に達したら「上限に達しました」と表示する。`maxLength` は入力を黙って止め、貼り付けた文章も黙って切り詰めるため、止まった理由が分かるようにする。
- 上限値は `src/constants/worksheet.ts` の `MAX_FIELD_LENGTH` に置き、入力欄と API の両方が参照する。
- API の入力上限は `MAX_FIELD_LENGTH × 項目数 + 500`（= 2600 文字）とし、項目の上限から算出する。300 × 7 = 2100 で旧上限の 2000 を超えるため、ラベルや感情の行の分の余裕を足した。

## Options Considered

### Option A: 入力欄は無制限のまま、API に送る前に本文を切り詰める

**Pros:** 書ける量に制限が無い。
**Cons:** AI は後ろの項目（反省・褒め言葉など）を読めないまま応答する。ユーザーからは切り詰めが見えない。

### Option B: 項目ごとに maxLength と警告を付け、API 上限を項目上限から算出する（採用）

**Pros:** 入力欄の上限内で書いた内容は、必ず全文が AI に届く。上限が 1 箇所に集約されるので、画面と API で値がずれない。
**Cons:** 1 項目 300 文字を超えて書きたい人は書けない。

### Option C: 全項目の合計文字数だけを制限する

**Pros:** 項目ごとの配分を利用者が自由に決められる。
**Cons:** どの項目を削ればよいかが分かりにくい。入力欄ごとの `maxLength` という標準の仕組みが使えない。

## Trade-off Analysis

ワークシートは「短く書き出して整理する」ためのもので、1 項目 300 文字あれば README の記入例の数倍を書ける。書ける量を制限する不便より、黙って定型文になる不具合をなくす利益を優先した。上限を定数 1 箇所から算出するのは、ADR-0013 と同じく値の食い違いを仕組みで防ぐためである。

## Consequences

- 画面の上限内で書いた入力が API で 400 になることはなくなった。
- 上限を変えるときは `MAX_FIELD_LENGTH` を 1 箇所変えるだけで、API の上限も追従する。
- 既存の記録で 300 文字を超えている項目はそのまま残る（表示にも影響しない）。
- `maxLength` はクライアント側の制限なので、Firestore ルールでの文字数の検証は今回も行っていない。書き込めるのは本人のデータだけなので、許容している。（2026-09-24 に ADR-0017 でルールでも 300 文字以下を検証するようにした）
