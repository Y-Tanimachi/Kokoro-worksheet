# Kokoro Worksheet

自分の感情を整理する CBT（認知行動療法）風ワークシートアプリです。日々の出来事と感情、そのとき頭に浮かんだ考えを4ステップで記録すると、AI からひと言の応援メッセージが届きます。たまった記録は週次・月次の感情レポートで振り返れます。

## できること

- Google アカウントでログインして、ワークシートを記録・閲覧する
- 感情（怒り、悲しみ、喜び、不安、疲労、無力感、愛情）を複数選び、強さを1〜10で記録する
- 保存すると Gemini が40〜70字の応援メッセージを生成する（失敗時も定型文で必ず返る）
- ホーム画面で今週・今月の感情レポートを見る（一番強い感情と、感情ごとの強度内訳）
- その日の記録がないと、12:00 と 18:00（JST）にプッシュ通知でリマインドが届く（ヘッダーのメニューで ON/OFF）
- PWA としてスマホのホーム画面に追加できる

## ワークシートの構成

入力は4ステップに分かれています。必須はステップ1の「何が起こったか」とステップ2の「感情」だけで、残りは書ける分だけ書けば大丈夫です。

| ステップ | 項目 | 内容 |
| --- | --- | --- |
| 1. きっかけ | 日付・時間 | 記録する日時（初期値は現在時刻、変更可） |
| | 何が起こったか | 感情が動いた具体的な出来事 |
| 2. 感情 | 感情（複数選択可） | 怒り、悲しみ、喜び、不安、疲労、無力感、愛情 |
| | 感情の強さ | 1〜10のスライダー。10が最も強い |
| 3. 思考と行動 | 自動思考 | そのとき、とっさに浮かんだ考え |
| | 代替思考 | 別の視点から見たら、どう考えられるか |
| | 反応 | 実際にとった行動や言動 |
| 4. 振り返り | 反省・学び | 何が良かったか、悪かったか |
| | 次に試すこと | 改善策や実行プラン |
| | 自分を褒めるポイント | 今日の自分に対するポジティブなひと言 |

保存が終わると、記録の内容をふまえた AI の応援メッセージが表示されます。

### 記入例（想定シーン：3歳のイヤイヤ）

| 項目 | 記入例 |
| --- | --- |
| 日付・時間 | 2026-02-02 18:15 |
| 何が起こったか | 3歳が「イヤイヤ」で洗濯物を落とさない |
| 感情 | 怒り、疲労、無力感 |
| 感情の強さ | 8 |
| 自動思考 | 「子どもは私を無視している。どうしていつもこうなの？」 |
| 代替思考 | 「子どもはまだ選択の方法を学んでいる。選択肢を与えてあげるべきかも」 |
| 反応 | 大声で叱った |
| 反省・学び | 叱る前に深呼吸ができず、相手の気持ちを見られていなかった |
| 次に試すこと | 洗濯物を置く場所を決めて、赤・青・緑の3色から選んでもらう |
| 自分を褒めるポイント | 片付けた部分を褒めて、笑顔で一緒に写真を撮った |

感情整理は自分を責めるためではなく、自分を知るためのツールです。書く内容に正解も間違いもありません。何度も書くうちに同じパターンが見えてきて、それが次の対処のヒントになります。

## 技術スタック

- Next.js（App Router）+ React + TypeScript
- Firebase（Auth / Firestore / Cloud Messaging）
- Gemini API（`@google/genai`。応援メッセージの生成）
- Tailwind CSS v4 + shadcn/ui スタイルの自作コンポーネント
- Vitest（ユニットテスト）
- デプロイ先は Vercel、通知バッチは Vercel Cron

## セットアップ

```bash
npm install
cp .env.example .env.local   # 各値を埋める
npm run dev
```

### 環境変数

`.env.example` に取得方法のコメント付きで一覧があります。

| 変数 | 用途 |
| --- | --- |
| `GEMINI_API_KEY` | 応援メッセージ生成（サーバー専用） |
| `FIREBASE_PROJECT_ID` / `FIREBASE_CLIENT_EMAIL` / `FIREBASE_PRIVATE_KEY` | Firebase Admin SDK（サーバー専用） |
| `NEXT_PUBLIC_FIREBASE_VAPID_KEY` | プッシュ通知の VAPID 公開鍵 |
| `CRON_SECRET` | 通知バッチの Bearer 認証用シークレット（Vercel Cron が自動付与） |

`FIREBASE_PRIVATE_KEY` は改行を `\n` リテラルに置換した1行の文字列にしてください。形式が違うと `npm run build` が `DECODER routines::unsupported` で落ちます（詳細は CLAUDE.md）。なお Firebase のクライアント設定（apiKey など公開可能な値）は `src/utils/firebase.ts` に直接書いてあるため、環境変数は不要です。

### コマンド

```bash
npm run dev          # 開発サーバー
npm run build        # 本番ビルド
npm run lint         # ESLint
npm test             # 全テスト（Vitest）
```

## 仕組みの概要

### データの保存先（Firestore）

| コレクション | 内容 |
| --- | --- |
| `users/{uid}/entries/{entryId}` | ワークシート本体 |
| `user_settings/{uid}` | 通知設定と FCM トークン |
| `user_limits/{uid}` | AI レートリミットのカウンター（サーバー専用） |

### API ルート

- `POST /api/ai-message` — Gemini で応援メッセージを生成。Firebase ID トークン検証、ユーザー別レートリミット、入力バリデーションで保護。生成に失敗しても定型文を返し、保存フローは止めない。
- `GET /api/notifications/send` — Vercel Cron（`vercel.json`、12:00 / 18:00 JST）から呼ばれ、当日の記録がないユーザーへ FCM プッシュを送る。無効になったトークンは自動で削除する。手動実行用に POST でも同じ処理を呼べる。

クロンを動かすには、Vercel のダッシュボードで環境変数 `CRON_SECRET` を設定します（Vercel がクロン呼び出し時に `Authorization: Bearer` ヘッダーとして自動付与します）。Hobby プランではクロン1本につき1日1回までのため、12:00 と 18:00 は別々のクロンとして登録しています。実行時刻は指定時刻から最大59分遅れることがあります。

### アイコンの差し替え

アイコンのファイル名は `src/constants/icon.ts` に集約されています。manifest（`src/app/manifest.ts`）・favicon（`src/app/layout.tsx` の `metadata.icons`）・FCM 通知（`src/app/api/notifications/send/route.ts`）はすべてこの定数を参照し、Service Worker（`public/firebase-messaging-sw.js`）は通知ペイロードに含まれる URL を使うため、コード側で書き換えるのは定数ファイル 1 箇所だけです（以前は 4 箇所に分かれており、manifest だけ更新してアイコンが約 2 か月 404 になっていたことがあります）。

**ファイル名は毎回変えます。** インストール済みの端末はアイコンを URL 単位でキャッシュするため、同じ名前に上書きしても更新されません。現行は末尾 `-2` なので、次は `-3` にします。

手順は次のとおりです。

1. 512x512 の PNG を用意する。maskable 用は端が円形に切り取られても成立するよう、中央 80% に収まる余白のある画像にする（`any` 用と同じ画像で済ませることもできますが、その場合は端が欠けます）
2. `public/icons/` に連番を上げた名前で**追加**する（`icon-512-3.png` と `icon-maskable-512-3.png`）
3. `src/constants/icon.ts` の `ICON_PATH` と `MASKABLE_ICON_PATH` を新しい名前に変える
4. 旧ファイルは消さない。古いマニフェストをキャッシュしたままの端末が参照している可能性があります

差し替え後は、デプロイ先をブラウザの DevTools で開き、Application > Manifest でアイコンが読めているかを確認してください。

開発時の設計方針（日付文字列の扱い、エントリ取得の方針など）は [CLAUDE.md](CLAUDE.md)、これまでの設計判断とその経緯は [docs/adr/](docs/adr/) にまとめてあります。
